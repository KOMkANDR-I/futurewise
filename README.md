# FUTUREWISE — краш-тест финансовых решений

> «Проверь решение до того, как оно станет реальностью».

FUTUREWISE — веб-MVP для сценарного стресс-тестирования личных финансовых решений: покупки, рассрочки, кредита, смены дохода, переезда, формирования подушки. Пользователь вводит свои параметры, добавляет неблагоприятные события и видит, **при каких условиях решение становится рискованным** — через помесячную модель остатка, поиск точки перелома, дерево последствий и сравнение альтернатив.

FUTUREWISE — инструмент сценарного анализа, а не финансовая консультация. Результаты — расчёт по введённым условиям, а не прогноз.

## Запуск

Требуется Node.js 18.18+ (рекомендуется 20 LTS или новее).

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # автотесты расчётного ядра (Vitest)
npm run typecheck  # проверка типов
npm run build && npm start   # продакшен-сборка
```

Без каких-либо ключей приложение работает полностью: AI-объяснения формируются локальными шаблонами из результатов расчёта.

## Пользовательский путь (1–2 минуты)

1. Главная → «Протестировать решение» (или «Посмотреть демо»).
2. Мастер из 4 шагов: ситуация → финансы → решение → стресс-события → «Запустить краш-тест».
3. **Результаты**: карточки показателей, график трёх режимов (базовый / неблагоприятный / стрессовый) с линиями нуля и резерва и отметками нарушений, помесячная таблица, допущения.
4. **Точка перелома**: пороги дохода, разового расхода, платежа, стоимости, взноса, перерыва в доходе; до/после порога; метод поиска и допущения.
5. **Дерево последствий**: ветви из событий сценария, клик по узлу → детали, редактирование условия, проверка действия.
6. **Альтернативы**: дешевле, больший взнос, ниже платёж, отложить, сначала резерв, сократить переменные расходы — на одном графике и в одной таблице, с компромиссами.
7. **AI-объяснение**: локальный разбор + вопросы о сценарии; при подключённом API и разрешении пользователя — объяснение языковой модели.

Справа на страницах сценария — панель параметров: любое изменение пересчитывает все разделы мгновенно и сохраняется.

## Расчётная модель

Для каждого месяца `m = 1…H`:

```
остаток_конец(m) = остаток_начало(m) + поступления(m) − расходы(m) − платежи(m)
остаток_начало(1) = текущие накопления
```

- Поступления: основной доход (с учётом смены дохода, снижений и задержек) + доп. доход (с учётом потерь) + поступления по решению (например, кредит «на счёт»).
- Расходы: обязательные + переменные + изменение расходов по решению + рост расходов от событий + неожиданные расходы.
- Платежи: действующие платежи + платежи по решению (взнос, рассрочка, кредит, комиссии) + новые платежи от событий.
- **Проверка остатка**: по умолчанию — на конец месяца (месячное приближение). В режиме «По дням» месяц моделируется как 30 условных дней: доход — в день зарплаты, платежи — в день платежей, разовые расходы событий — 15-го, регулярные расходы — равномерно; при совпадении дня списание идёт раньше поступления. Резерв и дефицит проверяются по самой низкой точке месяца (`lowPoint`) — так виден кассовый разрыв до зарплаты.
- **Расширенные допущения** (необязательные, по умолчанию выключены): годовая инфляция регулярных расходов, индексация доходов (помесячно, сложным процентом; платежи по кредитам не индексируются), ставка на положительный остаток (ежемесячное начисление).
- Кредит: аннуитет `P = S·r / (1 − (1+r)^−n)`, `r` — месячная ставка; график погашения с начислением процентов на остаток и корректировкой последнего платежа. Если пользователь ввёл свой платёж — используется он, а расхождение с аннуитетом показывается предупреждением. Комиссии разделяются на «учтено» и «неизвестно — принято 0».
- Режимы: **базовый** — без событий; **неблагоприятный** — события уровня «неблагоприятный»; **стрессовый** — все включённые события. Каждое событие применяется только в своём окне месяцев и ровно один раз.
- Условная шкала статусов (не процент риска и не кредитный рейтинг): «Резерв сохраняется» — минимум ≥ резерва; «Резерв нарушен» — 0 ≤ минимум < резерва; «Дефицит» — минимум < 0.
- Вероятности событий не придумываются. Если пользователь задал вероятность, она показывается отдельно от последствий и не смешивается с ними в «общий риск».

### Точка перелома

| Порог | Метод |
| --- | --- |
| Максимальное снижение основного дохода (на весь горизонт, поверх событий режима) | бинарный поиск, шаг 0,1% |
| Максимальный разовый расход в выбранном месяце | бинарный поиск, шаг 100 ₽ |
| Наибольший платёж по решению (при том же сроке) или новый ежемесячный платёж | бинарный поиск, шаг 100 ₽ |
| Максимальная стоимость покупки / сумма кредита | бинарный поиск, шаг 500 ₽ |
| Минимальный первоначальный взнос | систематический перебор (100 шагов) + уточнение до 100 ₽ — зависимость может быть немонотонной |
| Максимальный перерыв без дохода (смена дохода) | перебор по месяцам |
| Максимальный рост регулярных расходов (переезд, собственный сценарий) | бинарный поиск |
| Месяц первого нарушения резерва / дефицита | прямой расчёт |

Если условие выполняется во всём диапазоне поиска, порог **не придумывается** — показывается «не найдено». Для каждого порога видны: текущее значение, порог, результат до и после пересечения, предположения.

### Чувствительность и карта устойчивости

- **Торнадо**: каждый параметр (доход, расходы, накопления, стоимость, платёж, ставка, размеры событий) по отдельности сдвигается на ±10/20/30% при прочих равных; параметры сортируются по разбросу минимального остатка.
- **Карта устойчивости**: сетка 11 × 11 по двум выбранным параметрам (снижение дохода, разовый расход, накопления, резерв, стоимость, платёж, месяц исполнения). Каждая клетка — полный пересчёт модели; видна вся граница безопасной зоны, а не одна точка.

### Вероятностный взгляд

Строится **только** если пользователь сам задал вероятности событий. События считаются независимыми; события без вероятности не участвуют и перечисляются отдельно. При ≤ 12 событиях перебираются все 2^k комбинаций с весами (точный результат, без случайности), при большем числе — Монте-Карло с фиксированным зерном (воспроизводимо). Показываются: доля исходов с нарушением резерва и с дефицитом, квантили минимального остатка, веерный график по месяцам и условная доля нарушений «если событие случится / не случится». Это следствие пользовательских предположений, а не статистика и не скоринг.

## Подключение AI API

1. Скопируйте `.env.example` в `.env.local`.
2. Укажите провайдера и ключ:
   ```
   AI_PROVIDER=anthropic          # или openai — любой OpenAI-совместимый Chat Completions API
   AI_API_KEY=ваш_ключ
   AI_MODEL=claude-sonnet-5-5     # для openai — имя модели провайдера
   # AI_BASE_URL=https://api.openai.com/v1   # только для AI_PROVIDER=openai
   ```
3. Перезапустите `npm run dev`. На странице «AI-объяснение» появится статус «AI API подключён»; пользователь должен включить разрешение на отправку данных.

Как это устроено:
- Ключ читается только в `src/app/api/explain/route.ts` на сервере и в браузер не попадает.
- В модель передаётся структурированный объект (`buildAiPayload`): параметры, рассчитанные показатели по режимам, влияние событий, точки перелома, альтернативы, допущения, предупреждения. Название сценария не передаётся. Содержимое запроса видно пользователю.
- Системная инструкция запрещает модели придумывать числа, менять результаты ядра, предсказывать будущее, придумывать вероятности, оценивать кредитоспособность; требует разделять факты расчёта и предположения.
- Если ключа нет, провайдер недоступен или вернул ошибку — endpoint отвечает `source: "unavailable"`, и интерфейс использует локальные объяснения (`src/lib/explain/local.ts`).

## Постоянный адрес сайта (Vercel)

Временная ссылка через Cloudflare Tunnel работает, только пока включён компьютер. Чтобы адрес был постоянным:

1. Зарегистрируйтесь на [vercel.com](https://vercel.com) (можно через GitHub).
2. В папке проекта выполните и войдите в аккаунт в открывшемся браузере:
   ```bash
   npx vercel login
   ```
3. Опубликуйте:
   ```bash
   npx vercel --prod
   ```
   Vercel сам распознает Next.js. Переменные `AI_*` (если нужны) задаются в настройках проекта на Vercel → Settings → Environment Variables.

Другой путь — загрузить проект в GitHub и импортировать репозиторий на vercel.com/new: тогда каждое обновление будет выкладываться автоматически.

## Приватность

- Сценарии хранятся только в `localStorage` браузера; сервер их не получает.
- В AI API данные уходят только при подключённом ключе **и** явном разрешении пользователя.
- Не запрашиваются: банковские подключения, логины/пароли, номера карт и счетов, паспортные данные. Демосценарий — синтетический.

- Дерево последствий: ветви из событий, узлы с условием, результатом, моментом, статусом и действием; редактирование событий прямо из ветви; проверка и применение действия.
- Сравнение альтернатив: общий график, таблица одинаковых метрик, компромиссы, применение варианта к сценарию с подтверждением.
- AI-объяснение: локальный разбор (факты отдельно от предположений), чат с ответами по расчётам, серверный endpoint с fallback, согласие пользователя, просмотр отправляемых данных.
- Несколько сценариев: сохранение, открытие, редактирование, дублирование, удаление с подтверждением; живая панель параметров.
- Чувствительность: торнадо-анализ и интерактивная карта устойчивости по двум параметрам.
- Вероятностный взгляд по вероятностям пользователя: точный перебор комбинаций, веерный график, условные доли нарушений.
- Расширенные допущения: инфляция, индексация дохода, ставка на остаток, дневная модель месяца с поиском кассового разрыва.
- Отчёт для печати / PDF (светлая палитра при печати) и экспорт/импорт сценариев в JSON с проверкой схемы.
- **Долговая нагрузка (ПДН)**: доля дохода на кредиты — сейчас и в самый тяжёлый месяц каждого сценария, с ориентирами ЦБ 50% и 80% (не решение банка).
- **Несколько кредитов и рассрочек**: у каждого свой платёж, число оставшихся платежей и день списания; платёж заканчивается вовремя.
- **Кредит как в банке**: равные или убывающие платежи, досрочное погашение (меньше срок или меньше платёж), график, экономия на процентах, **ПСК** по формуле ЦБ для ежемесячных платежей.
- **Разброс**: доход и расходы «плавают» в заданных пользователем пределах; 600 пересчётов с фиксированным зерном, веерный график и доля плохих исходов.
- **Цели на шкале времени**: несколько целей по приоритету, когда накопите в каждом сценарии, успеваете ли к сроку.
- **Импорт выписки (CSV)**: автоопределение колонок, кодировки и категорий (доход / обязательные / на жизнь / кредиты / не учитывать), ручная правка, подстановка средних за месяц. Файл не покидает браузер.
- **Календарь платежей**: что и когда списывается внутри месяца, остаток по дням, самый трудный день.
- **Сравнение сохранённых сценариев**: таблица одинаковых показателей и общий график.
- **Куда уходят деньги**: диаграмма потоков от источников к тратам, в среднем или за выбранный месяц.
- **Подсказки для новичка** (запускаются один раз, повтор — кнопка «Подсказки») и **режим презентации** `/pitch` с живыми расчётами демо.
- **Установка на телефон (PWA)**: иконка, работа без сети для уже открытых страниц, кнопка «Установить» (на iPhone — подсказка).
- Тёмная/светлая тема, адаптивная вёрстка, клавиатурная навигация (радиогруппы со стрелками, доступные узлы дерева, skip-link), состояния загрузки, пустые состояния, ошибки валидации.
- Автотесты: базовый сценарий, отсутствие дохода, крупный расход, несколько событий в одном месяце, задержка дохода, нулевой остаток, нарушение резерва, отсутствие дефицита, демосценарий, неизменность исходных данных, сравнение альтернатив, точки перелома (с аналитической проверкой), аннуитет и график кредита, комиссии, валидация, дерево.

## Известные ограничения

- Дневная модель упрощена: 30 условных дней, все доходы в один день; платежи — в общий день или в день, указанный у кредита; налоги и кешбэк не учитываются.
- Долговая нагрузка считается от всего введённого дохода; банк использует подтверждённый доход и свои правила, поэтому его цифра может отличаться.
- ПСК считается по упрощённой формуле ЦБ для равных месячных периодов (без учёта точных дат платежей).
- Импорт выписки рассчитан на типичные CSV российских банков; если колонки не распознались, их можно выбрать вручную. Форматы PDF и XLSX не поддерживаются.
- Работа без сети: доступны страницы, которые уже открывались на устройстве.
- Инфляция и индексация — единые годовые ставки для всех расходов и доходов.
- Кредит: без плавающей ставки; комиссии — только разовые и фиксированные ежемесячные; досрочное погашение — без комиссии банка.
- Пороги ищутся по одному параметру за раз при прочих равных; взаимодействие нескольких параметров видно через альтернативы и ручные изменения.
- Вероятностный взгляд предполагает независимость событий и бинарный исход (событие либо случается целиком, либо нет); распределения размеров событий не моделируются.
- Хранение только в localStorage: сценарии не синхронизируются между устройствами и пропадут при очистке данных браузера.
- Локальный помощник распознаёт ограниченный набор тем вопросов; свободный диалог доступен при подключённом AI API.
